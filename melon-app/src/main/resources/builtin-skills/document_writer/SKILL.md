# 文本文档写作

面向工作区内的 Markdown 和纯文本文件，完成从需求澄清、结构设计到写入和审校的完整流程。

## 适用范围

- 新建或完善 README、方案、报告、说明书、会议纪要和操作手册。
- 把零散材料整理成结构清晰的文档。
- 在不改变事实含义的前提下压缩、扩写、改写或统一语气。
- 审校标题层级、术语、重复内容、遗漏和前后矛盾。

PDF、DOCX、XLSX、PPTX 等二进制文档不在本技能范围内。

## 工作流程

1. 明确读者、目的、使用场景、语言、篇幅、语气和必须保留的信息。
2. 若已有文件，先用 `read_file` 阅读相关内容；较长文档只读取完成任务所需的部分。
3. 提取事实、约束、待确认项和不可改动的专有名词。
4. 先确定标题结构和信息顺序，再撰写正文。
5. 新文件使用 `write_file`，局部修改优先使用 `edit_file`。
6. 写入后重新读取受影响部分，检查结构、事实和格式。
7. 向用户说明修改的文件和主要变化，不重复粘贴整篇文档。

## 写作原则

- 结论和行动项优先，背景信息只保留理解任务所需的内容。
- 一个段落表达一个中心意思，标题必须准确描述下方内容。
- 使用一致的术语、时间格式、数字单位和列表风格。
- 不把推测写成事实；缺少依据的内容标记为待确认。
- 不虚构引用、数据、接口、人员决定或完成状态。
- 保留用户已有的事实、约束和明确语气，除非用户要求重写。
- 对操作手册写清前置条件、步骤、验证方式、失败处理和回退方法。

## 常见文档结构

方案或设计：

1. 背景与目标
2. 范围与非目标
3. 约束与假设
4. 方案
5. 风险与应对
6. 验收标准

会议纪要：

1. 时间与参与者
2. 讨论结论
3. 决策
4. 行动项、负责人和截止时间
5. 待确认事项

操作手册：

1. 适用范围
2. 前置条件
3. 操作步骤
4. 验证
5. 故障处理
6. 回退

## 文件安全

- 只操作当前工作区内的目标文件。
- 覆盖已有文件前先读取现有内容，避免丢失用户修改。
- 不删除原始材料，除非用户明确要求。
- 不在文档中写入密钥、令牌、密码或不必要的个人信息。
- 涉及对外发布或发送时，只准备文档；实际发布或发送需要用户明确授权。
