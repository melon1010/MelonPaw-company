# 创建与维护 Skill

用于把已经明确、可重复执行的工作方法沉淀为当前 Agent 工作区中的技能。

## 适用场景

- 用户明确要求创建、修改、拆分、合并或删除 Skill。
- 同一类任务反复出现，步骤和边界已经稳定，值得复用。
- 现有 Skill 缺少触发条件、安全约束、参考资料或模板。

不适用：

- 一次性任务，不会复用。
- 流程仍不明确，需要先完成探索。
- 只是记录用户偏好，偏好应写入工作区记忆文件。

## 强制使用官方工具

所有技能变更使用 `skill_manage`，不要直接用 `write_file`、`edit_file` 或 Shell 修改 `skills/`。

支持的操作：

- `create`：创建包含完整 frontmatter 和正文的 `SKILL.md`。
- `edit`：完整替换现有 `SKILL.md`。
- `patch`：精确替换 `SKILL.md` 或支持文件中的一段内容。
- `write_file`：写入 `references/`、`templates/`、`scripts/` 或 `assets/`。
- `remove_file`：删除单个支持文件。
- `delete`：归档整个技能目录，不做永久删除。

这些操作可能触发审批。等待用户在审批界面确认，不要绕过审批流程。

## 创建流程

1. 明确技能解决的问题、触发条件、不触发条件和成功标准。
2. 检查是否已有职责相同的 Skill；能扩展现有技能时不要创建重复技能。
3. 选择简短稳定的名称，只使用小写字母、数字、点、下划线或连字符，最长 64 个字符。
4. 编写精确的 `description`，说明何时触发，并写清与相邻技能的边界。
5. 正文优先描述决策规则、执行顺序、失败处理和安全约束。
6. 调用 `skill_manage` 的 `create` 操作。
7. 只有正文确实过长或存在可复用素材时，才补充支持文件。
8. 创建后说明技能名称、用途和新增的支持文件。

## 最小模板

```markdown
---
name: example_skill
description: "当用户要求……时使用；不用于……。"
---

# 技能标题

## 适用场景

## 执行流程

## 失败与回退

## 安全约束
```

## 编写要求

- 只引用当前运行时真实存在的工具，不虚构工具名或参数。
- 能用正文讲清楚时不要新增脚本；脚本只承担确定、可测试的机械工作。
- 参考资料放入 `references/`，模板放入 `templates/`，可执行内容放入 `scripts/`，静态素材放入 `assets/`。
- 不写入密钥、令牌、密码、用户隐私、宿主机绝对路径或其他工作区路径。
- 外部发送、发布、上传、删除或权限变更必须保留用户确认。
- 不把某次任务的临时输入、文件名或偶然结论写成通用规则。
- 保持渐进披露：frontmatter 简洁，核心流程放正文，细节资料按需加载。

## 修改现有 Skill

- 小范围且有唯一匹配内容时使用 `patch`。
- 结构已经失效或需要大幅重写时使用 `edit`。
- 新增支持文件后，在 `SKILL.md` 中写清何时读取它。
- 删除技能前确认它没有被其他技能引用；使用 `delete` 归档，不要求永久删除。

## 完成检查

- 名称与 frontmatter 的 `name` 完全一致。
- `description` 能单独判断是否触发。
- 流程可执行，没有依赖未声明的工具或环境。
- 风险操作、失败路径和回退方式明确。
- 内容不与已有技能重复或冲突。
