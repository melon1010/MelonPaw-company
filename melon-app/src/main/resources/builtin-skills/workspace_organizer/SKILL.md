# 工作区整理

在当前 Agent 工作区边界内盘点和整理文件。默认保守处理，先建立清单，再执行可验证的小批量变更。

## 使用边界

- 单个文本文件的读取和总结使用 `file_reader`。
- 本技能处理目录结构、命名、归档和跨文件分类。
- 不访问其他用户、其他 Agent、宿主机或企业内网路径。

## 盘点流程

1. 明确目标目录、整理目的、命名规则、保留期限和不能移动的内容。
2. 使用 `glob_search` 或文件列表工具建立范围明确的文件清单。
3. 对名称不足以判断的文件，使用 `read_file` 读取最小必要片段。
4. 按类型、主题、时间、项目或生命周期提出分类方案。
5. 在变更前列出将新建、移动、重命名、合并或删除的项目。
6. 对覆盖、批量移动、批量重命名和删除操作先取得用户确认。
7. 分批执行，完成后重新列出受影响目录并核对遗漏。

## 默认目录建议

只有用户没有现成规范时才采用：

- `docs/`：长期维护的说明、方案和手册。
- `notes/`：过程笔记和临时研究记录。
- `data/`：结构化输入数据。
- `outputs/`：可交付结果。
- `assets/`：图片、视频和静态素材。
- `archive/`：不再活跃但需要保留的内容。

不要为了形式创建空目录，也不要把已有清晰结构强行改成这套结构。

## 命名原则

- 延续工作区已有风格，不混用多套规则。
- 名称应能独立表达内容，避免 `new`、`final2`、`temp-copy` 等含糊名称。
- 日期文件使用一致的绝对日期格式，例如 `2026-07-22`。
- 重命名前检查引用关系，避免破坏 Markdown 链接、配置路径或代码导入。

## 重复与归档

- 文件名相似不代表内容重复，合并前必须读取并比较。
- 冲突内容先保留两个版本并标记差异，不擅自选定权威版本。
- 默认归档而不是永久删除。
- 空目录只有在确认没有占位、挂载或工具约定用途后才删除。

## 完成报告

简要列出：

- 新结构或命名规则。
- 已移动、重命名、合并、归档或删除的数量。
- 因风险或信息不足而保留未动的项目。
- 需要用户继续决定的冲突。
